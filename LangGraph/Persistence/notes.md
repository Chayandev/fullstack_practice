## Persistence:
Persistence in LnagGraph referes to the abilit to save and restore the state or workflow of the graph. This is particularly useful when you want to save the state of the graph and restore it later, or when you want to save the state of the graph and restore it in a different environment.

- When a workflow is invoked , always the sate is a fresh no pastvalue is saved in that sate. so no history of conversation in state by default.

- So we have to save the state somewhere

- LangGraph provides a built-in persistence mechanism that allows you to save and restore the state of the graph. This is particularly useful when you want to save the state of the graph and restore it later, or when you want to save the state of the graph and restore it in a different environment.

- When a persistence is used in workflow , all the intermediate states are saved in the persistence store. So that when the workflow is invoked again, it can start from the last saved state.

- This helps in fault tolerance and recovery. If the workflow fails at any point, you can restore the state from the persistence store and continue the workflow from where it left off.

## Checkpointers in Persistence:

- Checkpointers are used to save the state of the graph at different points in the workflow. This allows you to save the state of the graph at different stages of the workflow and restore it later if needed.

- Every superset becomes checkpointer in workflow. and in each check point the sate of the graph is saved in RAM/DB.

- LangGraph provides built-in checkpointers that can be used to save and restore the state of the graph. These checkpointers can be used to save the state of the graph at different points in the workflow, such as after each step, after each node, or after each edge.

- The built-in checkpointers provided by LangGraph are:
    - MemorySaver: This checkpointer saves the state of the graph in memory. It is useful for testing and debugging purposes.
    - FileSaver: This checkpointer saves the state of the graph in a file. It is useful for saving the state of the graph in a file and restoring it later.
    - RedisSaver: This checkpointer saves the state of the graph in Redis. It is useful for saving the state of the graph in a Redis database and restoring it later.
    - DynamoDBSaver: This checkpointer saves the state of the graph in DynamoDB. It is useful for saving the state of the graph in a DynamoDB database and restoring it later

##  Threads in persistence

- When a workflow is invoked , it creates a thread in the persistence store. This thread is used to save the state of the graph at different points in the workflow.

- The thread is identified by a unique thread ID. This thread ID is used to save and restore the state of the graph.

- The thread ID is generated by the persistence store. The thread ID is unique for each thread in the persistence store.
